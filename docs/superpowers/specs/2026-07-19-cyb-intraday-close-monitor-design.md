# 创业板信号监控：盘中预估与收盘严谨双模式设计

## 目标

在现有创业板情绪信号监控基础上提供两个互不冲突的每日运行模式：

1. 周一至周五 14:40 发送盘中预估邮件，帮助用户在尾盘前了解可能出现的信号。
2. 周一至周五 15:20 发送收盘严谨邮件，更新正式策略状态并推送通达信副图。

盘中结果只用于预警，不得改变正式持仓状态。收盘结果是系统唯一的正式状态来源。

## 已确认方案

采用同一套监控程序加运行模式参数：

- `intraday`：盘中预估
- `close`：收盘严谨

两种模式共用行情解析、指标计算、策略规则和邮件基础模板，避免两套代码逐渐产生口径差异。

## 固定策略口径

本功能不修改既有交易策略，只修改数据时点和结果语义：

- 标的：创业板指 399006。
- 情绪：全市场上涨家数占有效涨跌家数的比例。
- 指标：现有 KDJ、均线和持仓/卖出规则保持不变。
- 盘中模式使用截至运行时刻的临时价格、当日最高价、最低价和实时涨跌分布，因此属于预估。
- 收盘模式只使用完整收盘数据，因此属于正式信号。

## 数据流

### 14:40 盘中预估

1. 请求腾讯创业板指数行情，允许保留当日尚未收盘的动态日K。
2. 请求同花顺当日实时涨跌分布。
3. 历史日期继续使用本地正式缓存；当天临时行情仅在内存中参与计算。
4. 在正式状态的副本上评估当天临时快照。
5. 生成盘中预估邮件。
6. 不保存策略状态、不覆盖正式日K或涨跌家数缓存、不生成正式通达信推送。

### 15:20 收盘严谨

1. 请求腾讯创业板指数日K，只保留已完成交易日。
2. 请求并补齐同花顺收盘涨跌分布。
3. 原子更新正式行情缓存。
4. 根据正式状态处理新增交易日并生成正式信号。
5. 邮件发送成功后原子保存正式策略状态。
6. 更新副图 CSV，并向通达信 TdxQuant 推送正式指标。

## 状态隔离

- `intraday` 可以读取正式状态，但禁止写回。
- `intraday` 不得改变 `processed_date`、持仓、最高收盘价或待执行信号。
- `close` 是唯一允许保存正式状态的模式。
- 盘中邮件发送失败或数据获取失败不能影响 15:20 正式任务。
- 如果正式状态缺失或损坏，盘中模式可以在内存中重放历史以形成预估，但仍不得保存；收盘模式沿用现有的历史重建与保存行为。

## 数据缓存

为防止盘中临时值污染严谨回测和正式信号：

- 盘中模式默认不写 `cyb_399006_daily.csv`。
- 盘中模式默认不写 `all_a_breadth_ths_2022_present.csv`。
- 盘中模式不写正式副图 CSV。
- 收盘模式沿用原子写入正式缓存。
- 盘中模式可读取现有缓存作为历史基础，但当天临时行只存在于本次进程内。

## 邮件

### 盘中邮件

- 标题必须含“盘中预估”。
- 正文必须包含运行时间、临时行情时间、临时指数价格、实时情绪和预估信号。
- 必须醒目标明“不是正式收盘信号，可能在收盘前变化”。
- 显示当前正式持仓状态和“若此刻收盘”的预估状态，但不得暗示正式状态已经改变。
- 每次任务运行都发送一封状态邮件，包括无信号或非交易日。

### 收盘邮件

- 标题必须含“收盘确认”或等价的正式标识。
- 正文包含正式数据日期、正式信号、状态变化和数据新鲜度。
- 保留现有“每次运行均发状态邮件”的行为。

### 当天盘中数据不可用

- 不使用前一交易日数据冒充当天盘中预估。
- 发送“盘中数据不可用/今日可能非交易日”的状态邮件。
- 不产生买入或卖出预估，不保存状态。

## 命令与批处理

监控脚本新增显式模式参数：

```text
python scripts/run_cyb_signal_monitor.py --mode intraday
python scripts/run_cyb_signal_monitor.py --mode close
```

批处理文件：

- 新增 `run_cyb_signal_monitor_intraday.bat`，只运行盘中模式。
- 新增 `run_cyb_signal_monitor_close.bat`，运行收盘模式并在成功后推送通达信。
- 现有 `run_cyb_signal_monitor.bat` 保持兼容，作为收盘严谨版入口。
- 后台任务设置 `CYB_SCHEDULED=1`，避免 `pause` 阻塞；手工双击仍保留暂停窗口。

## Windows 计划任务

在 Windows 任务计划程序中维护两个任务：

- `CYB Signal Monitor Intraday 14-40`
  - 周一至周五 14:40
  - 执行盘中批处理
- `CYB Signal Monitor Close 15-20`
  - 周一至周五 15:20
  - 执行收盘批处理

替换现有 `CYB Signal Monitor 14-40`，避免重复执行。两个任务均：

- 使用 Windows 用户 `Cindy` 的交互式登录令牌。
- 设置错过后尽快运行、允许电池运行、允许唤醒。
- 最长运行时间 30 分钟。
- 不依赖 Codex 自动化。

“周一至周五”不等同于交易所交易日。法定节假日仍可能启动任务，由程序通过当天数据是否存在判断并发送相应状态邮件。

## 错误处理

- 网络或解析失败：发送对应模式的错误邮件；不保存正式状态。
- 盘中缺失当天指数或情绪：发送不可用状态邮件，不产生预估信号。
- 收盘时仍缺失当天完整数据：发送正式数据错误邮件，不更新状态或通达信。
- 邮件发送失败：保持状态不变，返回非零退出码。
- 通达信推送失败：正式邮件和状态保存结果不回滚，但批处理返回非零并记录推送错误。

## 测试

采用测试驱动开发，至少覆盖：

- 盘中模式保留当天动态日K；收盘前严谨模式排除当天未完成日K。
- 盘中数据只在内存中使用，不修改三个正式缓存/状态文件。
- 盘中模式读取正式状态副本并计算预估，但不保存。
- 收盘模式邮件成功后保存状态。
- 盘中与收盘邮件标题、正文标识和风险提示不同。
- 缺失当天盘中数据时不复用昨日数据生成预估。
- 收盘数据缺失时不写状态、不推送通达信。
- 三个 BAT 的模式、错误码和计划任务环境标记正确。
- Windows 两个计划任务的时间、动作和下次运行时间正确。
- 现有监控、邮件、行情和全量测试无回归。

## 验收标准

- 14:40 收到明确标注的盘中预估邮件。
- 14:40 运行前后正式状态文件内容和修改时间不变。
- 15:20 收到收盘确认邮件，并在有新交易日时更新正式状态和通达信副图。
- 两个任务不会执行同一模式或重复发同一封邮件。
- Codex 关闭时 Windows 任务仍可运行；用户需保持 Windows 登录，电脑关机时无法按时执行。
