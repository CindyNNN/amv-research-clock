# 创业板情绪策略邮件监控工具设计

## 目标

构建一个可在 Windows 本地每日手工运行的研究监控工具。工具更新创业板指
399006 日线和同花顺全市场涨跌分布，计算严格口径市场情绪、KDJ 和 MA20，
根据已确认的策略状态机判断买入、卖出、持有或空仓无信号，并在每次运行后
向同一个 QQ 邮箱发送一封状态邮件。

工具只生成研究信号，不连接券商、不下单，也不读取任何交易账户凭据。

## 策略定义

### 指标

- 市场情绪：
  `上涨家数 / (上涨家数 + 平盘家数 + 下跌家数) × 100`
- KDJ：沿用现有回测的中国式 SMA 参数 `(9, 3, 3)`。
- MA20：最近 20 个交易日收盘价的简单移动平均。
- KDJ 死叉：当日 `K < D` 且上一交易日 `K >= D`。
- 最高收盘：模型持仓期间（含买入信号日之后的持仓日）的最高日收盘。

### 买入信号

模型为空仓，且当日收盘后同时满足：

- 市场情绪严格小于 15；
- KDJ 的 J 值严格小于 30。

当日状态记为“产生买入信号”，模型从该信号日起进入持仓状态。邮件明确说明
该信号在收盘数据形成后才能确认，实际执行只能参考下一交易日价格，不能把
回测的当天收盘价视为可保证成交价。

### 卖出信号

模型处于持仓状态，且当日收盘后满足以下任一条件：

1. 当日 KDJ 死叉，并且当日收盘严格低于 MA20；
2. 当日收盘小于或等于模型持仓期间最高收盘的 92%，即最高收盘回撤至少 8%。

卖出信号日结束后，模型转为空仓。邮件列出具体触发原因；若两个条件同时满足，
两个原因都列出。

### 无买卖信号

- 持仓但未满足卖出条件：`HOLD`。
- 空仓但未满足买入条件：`FLAT`。
- 每次运行均发送邮件，包括 `HOLD` 和 `FLAT`。

## 状态与幂等性

状态文件保存在项目本地运行目录中，包含：

- 模型是否持仓；
- 买入信号日期和信号日收盘；
- 持仓以来最高收盘及其日期；
- 最近处理的数据日期；
- 最近一次信号类型。

首次运行时，工具从 2020-01-01 起按照同一规则回放至最新数据，重建模型状态，
而不是默认用户真实账户持仓。此状态代表策略模型组合，不能替代用户实际账户。

同一交易日重复运行时：

- 仍按要求发送一封状态邮件；
- 不重复执行状态迁移；
- 不重复重置买入日期或最高收盘；
- 邮件标记本次结果为“同日重复检查”。

若状态文件缺失或损坏，工具从完整历史重新回放并在邮件中标记状态已重建。

## 数据流与组件

### 数据更新

复用现有创业板回测中的计算口径，但为监控工具提供动态结束日期：

- 创业板指日线：腾讯证券公开行情接口，代码 `sz399006`；
- 2022 年至今市场涨跌分布：同花顺涨跌分布接口；
- 2020–2021 历史情绪：现有本地重建数据，仅用于首次状态回放；
- 最新交易日必须同时具有指数日线和市场情绪，才允许判断信号。

监控不会重新下载全部历史涨跌分布，只补充本地缓存中缺少的交易日。

### 信号引擎

信号引擎为纯函数式状态转换：

`历史状态 + 最新完整指标行 -> 新状态 + 信号结果`

它不负责网络请求或发邮件，因此可用固定数据独立测试买入、两种卖出、持有、
空仓和同日重复运行。

### 邮件发送

QQ 邮箱使用：

- SMTP 主机：`smtp.qq.com`
- SSL 端口：`465`
- 发件人与收件人为同一个 QQ 邮箱
- 用户名来自环境变量 `CYB_QQ_EMAIL`
- SMTP 授权码来自环境变量 `CYB_QQ_AUTH_CODE`

授权码不会写入代码、状态文件、日志、邮件正文或错误报告。工具缺少配置时退出
并显示配置说明，不尝试发送。

邮件主题格式：

`[创业板情绪策略][BUY|SELL|HOLD|FLAT|ERROR] YYYY-MM-DD`

邮件正文包括：

- 信号类型和中文解释；
- 数据日期与本次运行时间（Asia/Shanghai）；
- 创业板指收盘、日涨跌幅；
- 市场情绪及上涨/平盘/下跌家数；
- K、D、J、MA20；
- 当前模型持仓状态；
- 持仓时的买入信号日期、最高收盘、8%回撤线和当前峰值回撤；
- 卖出条件逐项真假；
- 数据来源；
- “研究支持，不构成投资建议”的风险提示。

## 运行入口

提供两个入口：

1. Python CLI，支持正常运行和不发邮件的预览模式；
2. Windows 批处理文件，用户双击即可正常运行。

预览模式完整更新数据、计算信号和显示邮件内容，但不发送邮件，也不提交新的
持仓状态，用于首次配置前验证。

正常模式的处理顺序：

1. 检查邮箱环境变量；
2. 更新并校验数据；
3. 读取或重建策略状态；
4. 计算当日结果；
5. 发送邮件；
6. 仅在邮件发送成功后原子写入新状态。

将状态提交放在邮件成功之后，可以避免“状态已经变化但用户未收到信号邮件”。

## 错误处理

- 指数和情绪日期不一致：不生成交易信号，发送或显示 `ERROR`。
- 最新数据不是当天：允许非交易日运行，使用最近完整交易日并标注数据陈旧；
  同一数据日不迁移状态。
- 当天市场尚未收盘或接口仍为盘中数据：默认拒绝生成新信号，并提示在
  15:15 之后重试。
- 网络请求失败：最多重试三次；仍失败时保留原状态。
- 邮件发送失败：保留原状态，命令返回非零退出码。
- 指标缺失、数值越界或历史日期重复：拒绝生成信号并保留原状态。

## 文件边界

- `src/ai_invest_advisor/cyb_signal_monitor.py`：
  指标行、模型状态、信号结果和纯状态转换。
- `src/ai_invest_advisor/cyb_market_data.py`：
  动态更新指数与情绪缓存，并生成完整指标数据。
- `src/ai_invest_advisor/qq_email.py`：
  QQ SMTP 配置检查、邮件构建和发送。
- `scripts/run_cyb_signal_monitor.py`：
  CLI 编排、预览模式、状态原子提交和退出码。
- `run_cyb_signal_monitor.bat`：
  Windows 双击入口。
- `docs/cyb_email_monitor_usage.md`：
  QQ SMTP 授权码配置、预览、正式运行与故障排查说明。
- `data/monitor/cyb_emotion_strategy_state.json`：
  运行时模型状态，不包含邮箱凭据。
- `tests/test_cyb_signal_monitor.py`：
  信号状态机和历史回放测试。
- `tests/test_qq_email.py`：
  邮件配置和内容测试，SMTP 使用测试替身，不发送真实邮件。
- `tests/test_cyb_market_data.py`：
  数据对齐和动态日期测试，网络层使用固定响应。

## 验收标准

- 固定数据下可准确产生 BUY、两类 SELL、HOLD 和 FLAT。
- 首次运行能从历史回放出与逐日状态机一致的最终状态。
- 同一数据日重复运行不会二次迁移状态。
- 缺少邮箱环境变量时不会泄露或猜测凭据。
- 预览模式不发邮件、不修改状态。
- 正常模式只有在邮件成功后才提交状态。
- 邮件包含策略判断所需全部指标、数据来源、时间戳和风险提示。
- 全部新增测试和现有项目测试通过。
